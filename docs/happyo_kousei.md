# <スライド6>
一つ目が型についてです。 
プログラミングにおける型っていうのは   
ざっくりいうと
そのデータを何として扱うか

その型には２種類あって
一つは  
実行中に型が決まる「動的型付け言語」

書いた時点で型を決める「静的型付け言語」

この辺はみんな分かってると思うので  
具体的な説明は省きます。  

# <スライド7>
二つ目が実行方法について  
これは大きく分けて３つあります。

# <スライド8>
ソースコードを1行ずつ解釈して実行する  
インタプリタ型

ソースコードをいっかい  
機械語に翻訳してから実行する
コンパイル型

# <スライド9>
それぞれこういった言語が分類されます

# <スライド10>
三つ目がメモリ管理の方法です  
メモリ管理は  
使いたいメモリをどう確保し  
いつ解放するか  
っていう話です。
これだけRustの特徴に直結する話なので  
詳しく説明させてください。

# <スライド11>
まず
手動管理言語には  
C言語などがあります。  
人間が明示的に  
確保・解放を行う方法です。 

こういった感じで  
どこでどのくらいメモリが欲しいのか  
どのタイミングでいらないのか 
プログラマ自身が判断してコードに書かなくちゃいけません。

このメモリの解放を忘れると  
メモリリークっていう重大なバクにつながったりします

# <スライド12>
次が  
ガベージコレクションです。  
これはさっきのメモリの解放を機械がやってくれます。  
良さげに聞こえるんですが  
自動的に機会がやるってことは  
自分が書いた処理以外に  
そういう全部のメモリを参照して  
使われているかどうか判断して  
使われていなければ解放する  
っていう一連の処理が  
定期的に走るわけなので  
動作が重くなったり  
メインの処理が一瞬止まったりすることがあります。  

# <スライド13>
最後が  
所有権システムです  
これがRustのメモリ管理の方法なんですけど
これは簡単に言うと今までの２つの良いとこどりです。  

今どの関数がリソースを持っているかを
コードを書く時点で明示的に書く必要があります

# <スライド14>
例えば何も書かずに変数を受け渡すと
所有権ごと受け渡すことになります。

手動管理と違うところが   
所有権に関することをコード上で記述しないと  
スコープを抜けた時点で    
勝手にその変数がなくなります。    

で、そのなくなった変数を使おうとするとエラーがでてくれます


# <スライド15>
じゃあその所有権を渡さずに  
他の関数でその変数を使うにはどうしたらいいかというと  

こんな感じの＆をかいて
所有権は渡さないけどこの変数使っていいよー  
ってのを教えてあげます

つまり、メモリ解放し忘れによる
メモリリークの心配がないということです。
あとはGCみたいな重い処理が走ることもないので動作が軽いです。
